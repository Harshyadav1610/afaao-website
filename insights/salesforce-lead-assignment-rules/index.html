Salesforce lead assignment rules: how they work and how to fix them

By the Afaao team · November 24, 2026 · 6 min read

When a new lead lands in Salesforce with the wrong owner, or sits with the integration user, the cause is almost always the lead assignment rule. The feature is simple, but a few details about order, triggers and integrations trip up most teams.

Part of our Salesforce consulting guides.

Short answer

Salesforce lead assignment rules decide who owns a new lead. You can have one active lead assignment rule, made of rule entries that Salesforce checks in order; the first entry whose criteria match assigns the lead to a user or a queue. Rules run on web to lead, imports and manual creation when the assignment checkbox is used, and on API inserts only when the integration asks for them.

How lead assignment rules work

  • You can create several lead assignment rules, but only one can be active at a time.
  • The active rule contains rule entries. Salesforce checks them in order, from the lowest number up.
  • The first entry whose criteria match wins. Later entries are not checked.
  • Each entry assigns the lead to a user or a queue, and can send an email notification using a template you choose.

Because order matters, a broad entry near the top can quietly swallow leads that a more specific entry further down was meant to catch. Put the most specific entries first and the broadest last.

When the rule actually runs

  • Web to lead forms and lead imports, when you choose to use the active assignment rule.
  • Leads created or edited by hand, when the Assign using active assignment rule checkbox is selected.
  • Leads created through the API or an integration, only when the integration requests the assignment rule. If it does not, the lead stays with whoever created it, often an integration user.

That last point explains most mysteries. If leads from a marketing tool or form connector all land on one integration user, check whether that tool is set to use assignment rules. For HubSpot users, the same logic sits in the integration settings, and our guide to fixing HubSpot and Salesforce sync issues covers the related errors.

Round robin and fair distribution

Assignment rules do not rotate leads between reps on their own. A common native approach is to add an auto number field to leads, a formula field that uses MOD on that number to produce a value such as 1, 2 or 3, and one rule entry per value assigned to each rep. It works, but it does not know who is on holiday. Teams that need weighting, capacity or account matching usually add Flow logic or a routing tool.

Match leads to existing accounts first

A new lead from a company you already sell to should go to the account owner, not into the general rotation. Salesforce lead assignment rules do not match leads to accounts out of the box, so teams use Flow, duplicate and matching rules, or a dedicated routing tool. The idea is the same as in HubSpot, see lead to account matching in HubSpot.

Always have a fallback

Add a final rule entry with no criteria, or criteria that catch everything, that assigns to a queue a named person watches every day. A lead in a watched queue is always better than a lead sitting with an integration user.

A quick checklist

  1. Only the intended rule is active, and its entries are in the right order.
  2. Specific entries sit above broad ones, and a catch all entry is last.
  3. Every integration that creates leads is set to use the assignment rule.
  4. Inactive users and old queues are removed from entries.
  5. Existing account leads go to the account owner first.
  6. A daily view shows leads owned by integration users or sitting in queues too long.

FAQ

Quick answers

Can Salesforce have more than one active lead assignment rule?

No. You can create several lead assignment rules but only one can be active at a time. Use rule entries inside that rule to handle different cases.

Why are my Salesforce leads not being assigned?

The most common causes are an integration or import that does not use the active assignment rule, a rule entry order that sends leads to the wrong place, or no catch all entry at the end.
